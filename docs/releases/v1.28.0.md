# v1.28.0 — AI 多路检索与命中上下文改进

## 本次更新

- **多路 BM25 召回**：原问题与已有关键词分别检索，规范化去重后最多 4 路，用 RRF 融合排名；不新增模型查询改写调用。
- **按问题选择时间偏好**：明确近期问题才使用新近度权重；显式日期和历史倾向优先，减少旧记录被无条件降权的问题。
- **精排读取命中附近原文**：不再只看话题块开头两条；仍保持每候选最多 120 字及原精排调用预算。
- **长块覆盖多个命中点**：最多 17 条消息分配给多个命中窗口，按时间排列，跳过部分明确标注省略。
- **清理提问套话**：减少“请问群里有没有”等常见问句引起的无关召回。
- **检索诊断信息**：现有 ledger 返回各查询排名、候选、时间权重、精排预览与最终证据 ID，便于定位漏检阶段。

## 验证结果与边界

- `npm run check`：401 个单测、lint 和合成切群烟测。
- 60 个定向合成难例中，完整证据要求由 v1.27.1 的 30/60 到本轮 60/60；这组数据按已知失败机制构造，不代表真实准确率。
- 另 18 个手工合成案例，由 11/18 到 15/18；其中 3 个无证据题均通过，基线原先通过的题没有退化。
- **仍失败的 3 例**涉及旧决定、链接线索和纯语义表达，保留在评测集中。没有真实模型回答正确率、费用或端到端速度提升结论。
- 消融使用固定的保留全部候选模拟精排；详见仓库 [检索评测说明](https://github.com/alloevil/weibo-chat-auto/blob/v1.28.0/docs/retrieval-evaluation.md)，可离线复现。

## 使用注意

- 不增加向量库、embedding 服务、运行时依赖或 UI 开关。已有 AI 配置继续使用，真实问答仍会调用用户配置的模型服务。
- 多路检索增加本地计算；不承诺更快，也不保证没有词面交集的语义问题能被召回。
- `ledger.retrievalTrace` 含原文摘录，分享调试输出前请脱敏。默认不写磁盘，不应把候选相关性当作已验证的逐句引用支持。
- 不修改普通搜索框、历史日期、阅读位置或代码日志模式；不迁移原始群聊数据。

## 安装与升级

- macOS Apple Silicon：下载 `weibo-chat_v1.28.0_aarch64.app.zip` 并解压，替换旧应用。应用未签名，首次打开按 macOS 提示允许。
- 网页版：更新仓库，运行 `npm ci`，重启 `npm run view` 并刷新页面。
- 未新增其他桌面平台安装包；本地自动检查与构建不等于真实 macOS、微博接口或用户模型实机验收。
